# Добровольная лояльность и очистка контактов

Источник изменений — shared POS, см. web-source-manifest.json. Kotlin и финансовая модель не изменяются. Схема резервных копий остаётся 13, существующие ключи сохраняются; `privacyRules` хранит подтверждённые серверные инструкции отдельно от импортируемого файла.

Планшет передаёт сохранённую в оплаченном чеке версию согласия и время покупки. Старые очереди без версии не подключают клиента к программе. При прекращении участия сервер закрывает подарки и накопления, планшет получает инструкцию. Восстановление резервной копии проверяет актуальные инструкции на сервере до сохранения; для этого нужна сеть. Финансовые суммы, складское списание и данные для возврата остаются в чеке.

Сервер требует миграцию 005; автоматически начислять лояльность старое приложение после этого выпуска не сможет. Обновление устанавливается поверх прежнего приложения с той же подписью. Не удалять приложение: это может удалить локальные данные.

Проверки исходного POS, транспорта, JVM и сборка выполняются в GitHub Actions. Локальные тесты/линтер/сборка не запускались. Физическая приёмка остаётся за пользователем: обычный заказ без галочки, подключение с подтверждением Telegram, покупка/подарок, выход, повтор сети и восстановление старой копии после выхода.

Внешние файлы резервных копий и сообщения Telegram приложение удалить не может. Сроки финансовых документов и доказательств согласия определяются отдельно; их полное удаление не включается под видом очистки контактов.
