# Продажи при отрицательном остатке

В карточке простого товара → «Состав и остатки» появился чекбокс «Разрешить продажу при отрицательном остатке». По умолчанию выключен. Настройка хранится в products как allowNegativeStock=true/false и переносится существующим JSON backup.

Когда разрешение включено, товар можно добавить и оплатить при нуле и недостаточном остатке. Списание продолжает учитываться, например 0 − 2 = −2. Возврат использует исходное stockConsumption, поэтому восстанавливает количество даже после выключения настройки. Приёмки увеличивают отрицательный остаток обычным прибавлением. Выключение разрешения не обнуляет накопленный минус.

У составных товаров чекбокса нет. Их ингредиенты списываются по рецептуре: разрешение у одного ингредиента не разрешает нехватку другого. «Не вести учёт» остаётся отдельной настройкой и по-прежнему исключает товар из складского списания. Локальное разрешение продажи в минус не превращает физическую доступность сайта в бесконечную.

Общий исходник: b58ef5db99b5a1f63ab157c7144d1392253c2a66. Изменение Android adapter учитывает настройки при проверке резервов и сохраняет отрицательные значения в отображении. Платформенный Kotlin не изменялся. Проверки выполняются harness в Actions; физическая установка и проверка на планшете ожидаются.

## Отрицательное число на плитке составного товара

Общий источник отображения: 69fc113e75aabce18ef4d18ca31809b117718d1e. Плитки рабочей зоны и папок показывают расчётный дефицит составного товара по его ингредиентам, включая минус. Например, −0,4 кг ингредиента при расходе 0,2 кг на товар даёт −2. При частичном дефиците сохраняется правило целых продаваемых порций (−0,1 / 0,2 → −1). Неучётные ингредиенты исключаются как прежде.

Это отображение с учётом текущего и отложенных чеков. Доступность сайта остаётся неотрицательной; проверка разрешения продажи по каждому простому ингредиенту не меняется. Учётного собственного остатка у составного товара не появляется.
