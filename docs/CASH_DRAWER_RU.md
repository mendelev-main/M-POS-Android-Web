# Кассовый ящик через чековый принтер

Android Web отправляет отдельную команду ESC/POS открытия кассового ящика через LAN TCP/9100. Денежные решения остаются в общем JavaScript POS; Kotlin отвечает за проверку команды, транспорт и очередь принтера. Изображение чека, бумага и обрезчик сохраняют существующий путь.

## Когда открывается

- После надёжного сохранения наличной продажи или смешанной оплаты с положительной наличной частью, независимо от включённой автопечати чека.
- После сохранения возврата с наличной частью.
- После сохранения открытия смены, внесения или изъятия наличных.
- При открытии окна закрытия смены для подсчёта наличных. Повторное открытие окна — новое явное действие; сохранение закрытия использует тот же идентификатор и повторного импульса не добавляет.
- При пробной печати выбранного принтера ящика.
- По кнопке «Открыть кассовый ящик», доступной администратору в списке принтеров и на экране открытой смены. Отдельная система прав сотрудников не вводится: ручное открытие ограничено существующей ролью администратора.

При оплате только картой, нулевой наличной части, кухонной печати, повторной печати из истории и дополнительных копиях чека ящик не открывается. Старые операции и резервные копии при запуске не воспроизводятся.

## Настройки

Для существующей конфигурации используется первый включённый чековый принтер без явного запрета ящика. В настройках принтера есть флаг «Кассовый ящик подключён к этому принтеру». Его сохранение выбирает один принтер и отключает флаг у остальных; все явно отключённые ящики означают отсутствие автоматического открытия.

Команда по умолчанию: `1B,70,00,19,FA` — существующее значение проекта. Выход `00` соответствует первому выходу ящика; для некоторых моделей нужен `01`. Команду можно изменить в настройках. Разрешён только пятибайтный `ESC p`, выход 0/1/48/49, ненулевой импульс и пауза не короче импульса. Произвольные команды через это поле не отправляются. Совместимость конкретной модели Xprinter и нужный выход подтверждаются на оборудовании.

## Отправка и сбои

Для каждого адреса принтера используется отдельная последовательная очередь печати и открытия. Один идентификатор события допускает одну отправку в текущем процессе. Защита ограничена последними 256 событиями; на диске очередь открытия не хранится. Автоматического повтора после ошибки сети нет: принтер мог уже получить импульс. Администратор может проверить состояние и выполнить новое ручное открытие.

Успех транспорта означает отправку команды в сокет, а не подтверждение физического открытия ящика. Ошибка оборудования не отменяет сохранённую продажу, возврат или кассовое движение.

## Проверки и выпуск

Добавлены JS-проверки маршрутизации, наличной/смешанной оплаты, копий, перепечатки, выбора принтера, ручных прав, пробной печати, событий после сохранения и отказа хранилища. JVM-проверки проверяют точные байты команды, запрет других команд, дубликаты и передачу по локальному TCP-сокету.

Локальные JS/JVM-тесты, lint и сборка не запускались согласно AGENTS.md; результаты CI и подписанный APK фиксируются после завершения workflow. Текущая ревизия общего POS указана в `web-source-manifest.json`. Общий источник синхронизирован штатным `scripts/sync-pos-assets.py`; поведение ящика включено только при платформе Android и не меняет транспорт iPad.

Физическая приёмка: наличные, карта, смешанный платёж, повторная печать, 2–3 копии, возврат, смены и движения, пробная печать, ручной доступ, неправильный выход, отключённый принтер и восстановление сети без самопроизвольного повторного открытия. Эту приёмку нельзя подтвердить без планшета, принтера и ящика.
