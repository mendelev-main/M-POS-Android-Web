# Диагностика единиц заказа поставщику

Дата: 2026-10-09.

## Причина

Исходный makePurchaseLine отклоняет перевод между разными типами единиц: масса (кг/г), объём (л/мл), количество (шт.). До исправления общий текст «Несовместимые единицы измерения» не называл товар. Несовместимая единица сохранённого черновика могла отсутствовать среди отфильтрованных вариантов селектора, скрывая причину.

## Реализация

Внешний android-purchase-validation.js сохраняет исходные расчёты и журнал. Перед формированием проверяются все доступные простые товары черновика. Диалог перечисляет проблемные позиции, единицу заказа (для упаковки — единицу содержимого), складскую единицу и совместимые варианты. Кнопка «Перейти к товару» раскрывает новый заказ, прокручивает строку и фокусирует проблемное поле. Ошибочные строки отмечены рамкой и aria-invalid. Старая несовместимая единица явно отображается в селекторе.

При ошибке заказ не записывается, товары и введённые количества сохраняются. Автоматический перевод литров в килограммы не выполняется. Остальные проверки поставщика, блокировка финансовых операций и запись остаются в исходной реализации. Исходные файлы iPad не изменены; подключение адаптера поддерживается sync-pos-assets.py.

## Проверки

Добавлены четыре регрессии в source-product-stock.test.cjs: именованная ошибка и отсутствие записи; несколько ошибок и единица внутри коробки; совместимый пересчёт г/кг и успешное исходное формирование; экранирование имени товара и ошибочное количество. Тесты запускает GitHub Actions; локально наборы тестов, lint и APK не запускались согласно договорённости.

Вручную в браузере на синтетических данных проверены сообщение «Молоко: л / кг», явная несовместимая единица в строке и переход с фокусом к селектору. Это не проверка APK на планшете. Проверены синтаксис изменённого JavaScript и git diff. После сборки на планшете повторить исходный заказ: диалог должен назвать конкретные реальные товары; исправить единицы и сформировать заказ.
