Хеши исходного manifest не менялись.

## Что изменено

- Заголовок слева, компактная кнопка «Назад» справа; она не растягивается на ширину шапки.
- Вкладки «Программы»/«Клиенты», действия и окна используют геометрию «Товаров». В карточках программ видно условие и названия локальных товаров для накопления/подарка. Неизвестный локальному каталогу ID отображается без подмены данных.
- Поиск клиента закреплён сверху. Отдельный список занимает оставшуюся высоту, прокручивается касанием и доступен с клавиатуры. Enter убирает клавиатуру; есть очистка поиска, счётчик результатов и состояния ошибки/пустого списка.
- Результат поиска меняет только список, не заменяя поле ввода. Последовательность запросов и проверка текущего DOM отбрасывают старые ответы при новом поиске, смене вкладки и закрытии экрана. Начальная загрузка клиентов тоже не перерисовывает поле во время ввода.
- Первоначальное уменьшение всего WebView через IME padding заменено обработкой только окон: `adjustNothing`, неизменная высота рабочей зоны и ограничение окон видимой областью. Подробности и новый сценарий клиента текущего заказа — в [CUSTOMER_INPUT_KEYBOARD_RU.md](CUSTOMER_INPUT_KEYBOARD_RU.md).

Локальные продажи, чеки, начисления, сохранение, форматы данных и ручная синхронизация не изменены. Используются существующие handlers и GET поиска клиентов/списка программ.

## Проверка

Локальные JS/JVM тесты, lint и сборка APK не запускались согласно AGENTS.md. Написаны регрессии для Actions: навигация/экранирование, геометрия видимой области, отсутствие перерисовки при поиске, устаревшие ответы, ошибки и IME hosting. Сохранена проверка соответствия исходному manifest.

В браузере вручную просмотрены реальные Android-рендереры на синтетических программах и 24 клиентах: кнопка «Назад» справа, поиск, карточки, независимая прокрутка списка до конца. Это визуальная проверка, не проверка системной Android-клавиатуры.

Проверить открытие клиента, возвращение назад и редактирование программы. Физическая приёмка остаётся за пользователем.
