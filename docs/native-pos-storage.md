# Локальное хранение Android POS

В выпуске с native persistence `prilavok_` строки хранятся в приватной SQLite `pos-storage.db`. Web runtime, JSON, keys, backup, склад/деньги и журнал остаются прежними. Синхронная façade localStorage подтверждает запись только после SQLite commit; старое ограничение WebView на несколько МиБ не применяется. Kotlin хранит строки, не рассчитывает продажи.

При первом запуске снимается read-only копия всех `prilavok_` строк WebView, включая незавершённый журнал. Одна SQLite-транзакция записывает и проверяет точное чтение каждой строки, затем ставит маркер завершённого переноса. Сбой откатывает все части и маркер. Исходная WebView-копия не удаляется. После маркера она больше не импортируется: это устаревший резерв, а не текущая база. Удаление данных приложения и установка старого APK не являются восстановлением. Экспорт текущей проверенной копии — через штатные настройки M POS.

Большие строки разбиваются по 65536 UTF-16 символов с сохранением суррогатных пар. Каждая строка читается по частям, а её замена/удаление выполняется одной SQLite-транзакцией; CursorWindow не получает многомегабайтный orders целиком.

Один @JavascriptInterface.call принимает JSON-команду и токен сеанса. Токен генерируется на каждый WebView, передаётся в closure только главного appassets origin через DOCUMENT_START_SCRIPT; не сохраняется в БД/логах. Без токена команды отклоняются до доступа к БД. Команды ограничены namespace и key/value, произвольные SQL и пути недоступны. Существующий postMessage bridge остаётся origin-restricted. Старый WebView без DOCUMENT_START_SCRIPT не получает обходного незащищённого доступа.

Если открыть/мигрировать SQLite не удалось, startup guard останавливает POS до загрузки пустых fallback данных и показывает ошибку. Нет автоматического fallback к устаревшему WebView, очистки чеков или сброса защиты. При реальном заполнении диска запись по-прежнему блокируется.

Проверки: tests/android-storage.test.cjs, регрессии реального JS payment/recovery в source-product-stock, PosKeyValueStoreTest Robolectric. Отдельно требуется установка обновления поверх проблемного устройства, проверка старых чеков, оплата, печать, перезапуск, повторный экспорт резервной копии.

Также переносятся два прежних ключа принтеров: `printers` и `posNotificationSettings`. Они входят в разрешённое пространство, а прочие не-POS ключи остаются у исходного провайдера.
