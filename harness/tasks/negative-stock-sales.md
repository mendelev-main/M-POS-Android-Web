# Продажа при отрицательном остатке

## Согласованное поведение

Чекбокс «Разрешить продажу при отрицательном остатке» — только у простого товара, в разделе «Состав и остатки». У составных товаров настройки нет: нехватка каждого ингредиента проверяется по его собственной настройке. По умолчанию разрешение выключено. Это не отключает учёт: продажи уменьшают реальный остаток, включая отрицательные значения; возврат восстанавливает историческое списание. «Не вести учёт» сохраняет прежнюю независимую семантику.

## Объём

Общий runtime: карточка/dirty tracking/сохранение, проверка продаж, доступность плиток, списание оплаты. Android adapter: резервирование отложенных заказов и проекция остатков плиток. Схема products расширяется boolean allowNegativeStock, прежние поля/ключи/история списания не меняются. Сайт продолжает получать физическую доступность, а не бесконечный остаток из локального разрешения продажи.

## Проверки

- Простые товары: default запрет, включение, повторные продажи в минус, выключение, сохранение и storage failure.
- Рецепты: разрешённый ингредиент не снимает ограничений остальных; флаг составного товара игнорируется; модификаторы проверяются самостоятельно.
- Оплата: отрицательный остаток сохраняется вместе с историческим списанием; storage failure не меняет state; возврат точный независимо от текущей настройки.
- Android: отложенные резервы сохраняются для ограниченных товаров, разрешённые не блокируются нехваткой, дробные списания не округляются на каждой операции.
- UI: checkbox только для простого товара; 1280×800 и 1024×768.
- Harness preflight, JS / JVM / lint в Actions; APK с прежними identity/certificate.

Физический планшет не подключён. Не считать предпросмотр приёмкой оборудования.
