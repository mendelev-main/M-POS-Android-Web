# Переполнение localStorage: 2026-11-06

Подтверждено на устройстве: QuotaExceededError при write criticalStorageJournal; 2.66 МиБ символов всего, orders 2.17 МиБ. Удаление/усечение чеков запрещено.

Решение: Android-only синхронный key/value SQLite persistence adapter, неизменные prilavok_ ключи и JSON, тот же JS-журнал и порядок подтверждения. SQLite хранит строки частями, чтобы большие orders не упирались в CursorWindow. Единственная JavascriptInterface-команда требует непредсказуемый токен; функция с токеном внедряется до загрузки только в главный доверенный origin. Никаких SQL/файловых путей из JS.

Первый запуск: снять все исходные строки, единая транзакция копирования + проверка точного чтения + маркер. Исходные localStorage строки не удалять. После маркера всегда использовать SQLite; не импортировать устаревшую копию повторно. Ошибка инициализации блокирует старт POS, не подменяет данные пустыми значениями. Старые неполные журналы переносятся и воспроизводятся существующим механизмом.

Проверки в Actions: Kotlin SQLite >5 МиБ, Unicode chunk boundary, атомарность сбоя, повторный запуск/маркер, валидация/token; JS façade >5 МиБ, migration failure, no fallback, текущий чек/оплата/восстановление журнала. Preflight до/после, APK identity/runtime. Локальные тесты не запускать. Физическая установка поверх 1.0.127-1 и сохранение реального чека требуют устройства пользователя.
