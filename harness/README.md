# Harness для Codex

Это рабочий контур данного репозитория: постоянный контекст, порядок изменения кода, исполняемые проверки и наблюдаемые результаты. Он используется через корневой `AGENTS.md` и GitHub Actions. Отдельная установка сервиса или API-ключ не нужны.

Начало каждой задачи:

1. Прочитать `AGENTS.md`, [архитектуру](architecture.md), [порядок работы](workflow.md) и последнюю запись [журнала](build-log.md).
2. Проверить `git status --short`, определить затрагиваемый слой и выполнить `python3 scripts/harness.py preflight`.
3. Исправить задачу и пройти соответствующие проверки. Записать реальные результаты и оставшиеся ограничения.

Команды запускаются из корня репозитория, Python 3.9+:

| Команда | Назначение | Где запускать |
| --- | --- | --- |
| `python3 scripts/harness.py preflight` | Целостность закреплённого web-источника, наличие контекста, согласованность package | Локально и в CI, без исполнения приложения |
| `python3 scripts/harness.py js` | Весь существующий набор Node.js-тестов | GitHub Actions, Node 24 |
| `python3 scripts/harness.py android` | JVM-тесты и lint существующего Gradle-проекта | GitHub Actions, JDK 17 и Android SDK |

Локальный запуск тестов требует отдельного прямого указания пользователя и флага `--allow-local-tests`; запрос «используй harness» сам по себе его не даёт. Скрипт не устанавливает зависимости, не синхронизирует исходник и не публикует изменения. Результаты команд и логи находятся в `build/harness/`, в CI попадают в артефакт отчётов. Красный результат останавливает команду и выпуск APK.

Preflight подтверждает совпадение с локальным manifest, но не доказывает подлинность upstream, корректность бизнес-логики, сертификат готового APK или работу оборудования. Для этого остаются тесты, `verify-apk.py` и физическая приёмка.

Подход адаптирован из [официального руководства OpenAI](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex). Существующие правила проекта имеют приоритет.
